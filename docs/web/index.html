Building an Ultra-Low-Power Edge AI System with DEEPX M1 NPU and Raspberry Pi 5

Recent advances in edge AI enable real-time execution of complex models on-device, eliminating the need for cloud-based processing. Limited power, heat, and compute on embedded boards remain key challenges for engineers.

This article demonstrates how to combine the widely used Raspberry Pi 5 single-board computer with DEEPX's ultra-low-power, high-performance DX-M1 M.2 AI accelerator into a capable edge AI system. We walk through the full workflow—from hardware architecture to training and porting a custom wildlife detection model, and a practical wildlife monitoring camera demo.

1 DEEPX NPU Introduction: High Performance and Ultra-Low Power

HW Architecture and Ultra-Low-Power Design

DEEPX DX-M1 is built on a 5 nm process and delivers 25 TOPS (INT8) tuned for edge use. The design optimizes inference performance per watt—not only process node or peak TOPS—through custom architecture optimization.

Power metrics demonstrate the benefit clearly. YOLOv9T runs at about 2.69 W; even the heavier YOLOv8L stays near 5.64 W. A small heatsink or fan is enough to operate alongside Raspberry Pi 5.

Internal Block Diagram and Memory Hierarchy

The DX-M1 chip includes Cortex-M55 cores and three NPU cores (NPU0, NPU1, NPU2) for parallel compute. It supports LPDDR5; the M.2 module has two 2 GB LPDDR devices and connects to the host over PCIe Gen3 x4.

The memory hierarchy optimizes data reuse to alleviate bandwidth constraints. Deep learning often hits memory bandwidth limits; DX-M1 uses on-chip SRAM and tuned data flow to cut external accesses for weights and activations.

2 Turning Raspberry Pi 5 into an Edge AI System with the DX-M1 M.2 NPU

M.2 NPU Module Overview and Hardware Installation

The DEEPX DX-M1 M.2 module adopts the standard M.2 2280 Key M form factor. Raspberry Pi 5 supports PCIe officially, so you can mount the NPU with an NVMe HAT or M.2 expansion board.


DX-M1M Module Overview and Integrated HAT Installation

The DEEPX DX-M1M chip is a solution with 1 GB or 2 GB of DDR4 RAM built in. Through collaboration between DEEPX and Sixfab, they offer a product with the DX-M1M chip mounted on-board, providing an AI HAT form factor verified for Raspberry Pi 5. You can install and use the hardware as shown below.

3 Cross-Platform Development: Custom AI Model Porting

Next, we will construct a practical wildlife detection camera system. Note that model compilation and execution are performed in separate environments: compilation occurs on the host, while inference is deployed on the target.

Split model development (wildlife detection) from inference deployment. Train and convert to .dxnn on a capable host PC; build applications on the edge device (e.g., Raspberry Pi 5 + DX-M1 M.2) that execute on DX-Runtime.

The vision AI development workflow consists of five steps:

  1. AI Use Case: Run object detection with YOLO26.
  2. Data Preparation: Collect a training dataset and annotate images. See Appendix 4 for details.
  3. Training: Train a YOLO26 model for wildlife detection on your dataset. See Appendix 4 for details.
  4. Optimization with DX-Compiler: Convert pre-trained PyTorch weights to ONNX, then to .dxnn for the DEEPX NPU. Appendix 4 covers cloud export via Ultralytics; here we compile locally with DX-COM.
  5. Deployment: Build and run an object detection app that infers on the DEEPX NPU using your .dxnn file.

[Host PC] Compile the Wildlife Detection Model to .dxnn for DEEPX

DEEPX compiler DX-COM runs only on x86_64 PCs. Perform model training and binary compilation on a development PC (Debian-based Linux recommended). The host machine operates independently of the DX-M1 M.2 module during compilation. Export ONNX from a PyTorch .pt file (e.g., YOLO26s), then use DX-COM to produce .dxnn.

  1. Download pre-trained YOLO26s weights: Download weights for the wildlife YOLO26 model based on YOLO26s. You get yolo26s-custom.pt. (We provide the .pt file for convenience; you may train your own custom model instead.)

    💻 Host PC (Ubuntu/x86_64) 
    wget -O yolo26s-custom.pt https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/best.pt

  2. Install packages: Open a terminal, create a Python virtual environment, and run pip install ultralytics. The setup process takes only a few minutes to complete.

    💻 Host PC (Ubuntu/x86_64) 
    # Create and activate Python virtual environment
python -m venv venv
source venv/bin/activate
pip install -U pip

# Install ultralytics & dx-com package
pip install ultralytics dx-com

  3. Export to ONNX: DX-Compiler needs ONNX first, then .dxnn. Fix batch size to 1 for export. The NPU is tuned for low latency with a single fixed batch, not multi-batch.

    💻 Host PC (Ubuntu/x86_64) 
    # Export to ONNX with yolo export (input size = 640, batch size = 1)
yolo export model=yolo26s-custom.pt format=onnx batch=1 imgsz=640
# wget -O yolo26s-wild.pt https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/yolo26s-custom.onnx

    Success when yolo26s-custom.onnx exists. Open it in https://netron.app, click the top images layer, and confirm input shape 1x3x640x640.

  4. Prepare calibration data: DX-Compiler requires calibration images for FP32 to INT8 quantization; 100 or more are recommended. The closer the images are to the actual input dataset, the more you can minimize accuracy loss. However, using calibration images that differ from the actual deployment environment during compile means real data is not reflected in quantization, which can reduce INT8 accuracy—take care to avoid this. This guide uses an arbitrary dataset, but in production you must use a dataset matched to your deployment environment.

    💻 Host PC (Ubuntu/x86_64) 
    # Download calibration images for FP32 to INT8 quantization in DX-Compiler
wget "https://sdk.deepx.ai/dataset/calibration_dataset.tar.gz"
tar xzf calibration_dataset.tar.gz

  5. Create compile config: Create yolo26s-custom.json as below. See the DX-COM user manual on the DEEPX developer site (sign in required). Download: https://developer.deepx.ai/download/?id=510

    💻 Host PC (Ubuntu/x86_64) 
    {
  "inputs": { "images": [1, 3, 640, 640] },
  "calibration_num": 100,
  "calibration_method": "ema",
  "train_batchsize": 32,
  "num_samples": 1024,
  "default_loader": {
    "dataset_path": "calibration_dataset",
    "file_extensions": ["jpeg", "jpg", "png", "JPEG"],
    "preprocessings": [
      { "resize": { "mode": "pad", "size": 640, "pad_location": "edge", "pad_value": [114, 114, 114] } },
      { "div": { "x": 255 } },
      { "convertColor": { "form": "BGR2RGB" } },
      { "transpose": { "axis": [2, 0, 1] } },
      { "expandDim": { "axis": 0 } }
    ]
  }
}

  6. Compile with DX-COM: Run the command below when config is ready. See the DX-COM user manual on the DEEPX developer site. Download: https://developer.deepx.ai/download/?id=510

    💻 Host PC (Ubuntu/x86_64) 
    dxcom -m yolo26s-custom.onnx -c yolo26s-custom.json -o output

# After compile, yolo26s-custom.dxnn is created under output/
# ├── output
# │   └── yolo26s-custom.dxnn

    Copy yolo26s-custom.dxnn to the target (Raspberry Pi 5). To skip compilation, download a pre-built wildlife yolo26s-custom.dxnn from the link below.

    💻 Host PC (Ubuntu/x86_64) 
    wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/yolo26s-custom.dxnn"

  5. Four-stream GStreamer pipeline: Build and deploy a 4-stream pipeline with your .dxnn and test videos.

    🍓 Target (Raspberry Pi 5) 
    #!/bin/bash
# =========================================================
# Configuration (user settings)
# =========================================================
NUM_PIPELINES=4
OUTPUT_WIDTH=1280
OUTPUT_HEIGHT=720

MODEL_NAME="yolo26s-custom.dxnn"
POSTPROCESS_LIB="/usr/local/share/gstdxstream/lib/libpostprocess_yolo26od.so"

# =========================================================
# Grid Layout Calculation
# =========================================================
COLS=1
while [[ $((COLS * COLS)) -lt ${NUM_PIPELINES} ]]; do
    COLS=$((COLS + 1))
done
ROWS=$(((NUM_PIPELINES + COLS - 1) / COLS))

STREAM_WIDTH=$((OUTPUT_WIDTH / COLS))
STREAM_HEIGHT=$((OUTPUT_HEIGHT / ROWS))

echo "=================================================="
echo " Pipeline Configuration"
echo " - Streams: ${NUM_PIPELINES}"
echo " - Grid: ${ROWS} rows x ${COLS} columns"
echo " - Individual Stream Size: ${STREAM_WIDTH}x${STREAM_HEIGHT}"
echo " - Total Output Resolution: ${OUTPUT_WIDTH}x${OUTPUT_HEIGHT}"
echo "=================================================="

# =========================================================
# Pipeline Generation
# =========================================================
PIPELINE_STR=""
COMPOSITOR_PROPS=""

for i in $(seq 0 $((NUM_PIPELINES - 1))); do
    VIDEO_FILE="test-video-$((i+1)).mp4"
    URI="file://$(pwd)/${VIDEO_FILE}"

    # Calculate x, y positions for the compositor
    ROW_IDX=$((i / COLS))
    COL_IDX=$((i % COLS))
    X_POS=$((COL_IDX * STREAM_WIDTH))
    Y_POS=$((ROW_IDX * STREAM_HEIGHT))

    echo " Adding stream ${i}: ${VIDEO_FILE}"

    # Build the individual stream pipeline
    SRC_PIPE="urisourcebin uri=\"${URI}\" ! queue max-size-buffers=6 ! decodebin ! queue max-size-buffers=6 ! \
        dxpreprocess preprocess-id=1 resize-width=640 resize-height=640 ! queue max-size-buffers=6 ! \
        dxinfer preprocess-id=1 inference-id=1 model-path=\"${MODEL_NAME}\" ! queue max-size-buffers=6 ! \
        dxpostprocess inference-id=1 library-file-path=\"${POSTPROCESS_LIB}\" function-name=PostProcess ! queue max-size-buffers=6 ! \
        dxosd ! queue max-size-buffers=6 ! \
        dxscale width=${STREAM_WIDTH} height=${STREAM_HEIGHT} ! queue max-size-buffers=6 ! comp.sink_${i}"

    PIPELINE_STR="${PIPELINE_STR} ${SRC_PIPE}"
    COMPOSITOR_PROPS="${COMPOSITOR_PROPS} sink_${i}::xpos=${X_POS} sink_${i}::ypos=${Y_POS}"
done

# =========================================================
# Launch Pipeline
# =========================================================
LAUNCH_CMD="gst-launch-1.0 -e ${PIPELINE_STR} compositor name=comp ${COMPOSITOR_PROPS} ! videoconvert ! fpsdisplaysink sync=false"

echo "--------------------------------------------------"
echo "Launching GStreamer pipeline..."
echo "--------------------------------------------------"

eval "${LAUNCH_CMD}"

exit 0
💡 Tip: When all streams use the same model, you do not need separate dxpreprocess → dxinfer → dxpostprocess chains per stream. Use dxinputselector and dxoutputselector to share plugins and avoid loading the same model on the NPU multiple times.

4 Appendix: Training Your Own YOLO26 Custom Model

YOLO26 is a vision model optimized for edge devices with end-to-end inference (no NMS post-processing). This guide covers two training workflows, suitable for both beginners and experienced developers.

A sample dataset is available at the link below. It is small due to licensing—use it only to learn the layout. For research-grade accuracy, you need a dataset of at least 1,000 images. For commercial-grade accuracy, you need at least 10,000 diverse images in your dataset.

👉 Download: https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/dataset.tar.gz


Dataset Layout and Folder Structure

Training needs images plus label files with bounding boxes. Ultralytics supports YOLO, COCO, VOC, and more. A typical custom dataset layout:

💻 Host PC (Data Prep) 
dataset/
├── data.yaml          # Config: class names and train/val paths
├── images/
│   ├── train/         # Training images (.jpg, .png, etc.)
│   └── val/           # Validation images
└── labels/
    ├── train/         # Label .txt files (same base name as train images)
    └── val/           # Validation label files

For a 4-class person/wildlife model, data.yaml looks like this:

💻 Host PC (Data Prep) 
# YOLO detection - 4 custom classes
train: images/train
val: images/val

names:
  0: Person
  1: Deer
  2: Raccoon
  3: Bear

For more details on YOLO dataset, refer to the following Ultralytics YOLO Dataset Overview.
👉 Download: https://docs.ultralytics.com/datasets/detect#how-do-i-start-training-a-yolo26-model-using-my-dataset

Training Method 1: Ultralytics Platform (Cloud, Beginner-Friendly)

Train in the browser without local setup or coding.

  1. Sign in and upload: Log in at https://platform.ultralytics.com, create a project, and upload images.
  2. Smart labeling: Use Smart Annotation to auto-draw boxes—up to ~10× faster than manual labeling.
  3. Cloud Training - New Model: After labeling, start training on cloud GPUs, watch metrics live, and choose New Model.

  4. Cloud Training - Base Model: Pick the base YOLO model for training.

  5. Cloud Training - Start Training: Cloud training is paid (~$0.34 credit for ~1,300 images with yolo26n). Business email sign-up includes $25 free credit.

  6. Export: Export the trained model to get yolo26n.dxnn for direct NPU inference.

For more details, refer to the following Ultralytics DEEPX Integration Guide.
👉 Link: https://github.com/ultralytics/ultralytics/blob/main/docs/en/integrations/deepx.md

YOLO26 Performance by Model Scale

In YOLO26 names, n, s, m, l, and x denote size and compute. In short, they trade model size (parameters) for speed.

  1. n (Nano): Smallest, lightest (speed first, tiny devices)
  2. s (Small): Small model (balanced speed and accuracy)
  3. m (Medium): Medium size (balanced overall)
  4. l (Large): Large model (when you need higher accuracy)
  5. x (XLarge): Largest (accuracy over speed)

Benchmark results on Raspberry Pi 5 + DX-M1 M.2:

Model (640x640) FPS Accuracy (mAP)
YOLO26n 110.56 39.256
YOLO26s 109.96 46.767
YOLO26m 96.81 51.261
YOLO26l 70.10 53.149
YOLO26x 40.12 55.115

The .dxnn files used for these measurements were downloaded from the DEEPX Official Model Zoo (https://developer.deepx.ai/modelzoo/).

Example benchmark command: run_model -m yolo26s.dxnn --use-ort -t 3 (change model name per scale: yolo26n.dxnn, yolo26s.dxnn, etc.)
