DEEPX M1 NPU と Raspberry Pi 5 で構築する超低消費電力 Edge AI システム

近年の Edge AI 技術の進歩により、重いクラウドサーバーを経由せず、デバイス上で複雑な AI モデルをリアルタイムに処理できるようになった。しかし、限られた電力と発熱、そして組み込みボードのコンピューティングリソースの制約は、依然としてエンジニアが解決すべき課題である。

本稿では、世界で最も広く使われているシングルボードコンピュータ「Raspberry Pi 5」と、DEEPX の超低消費電力・高性能 AI アクセラレータ「DX-M1 M.2 モジュール」を組み合わせ、強力な Edge AI システムを構築する方法を紹介する。ハードウェアのアーキテクチャから始め、野生動物を認識するカスタムモデルの開発・ポーティング、そして実践的な野生動物監視カメラデモまで、Edge AI 開発のワークフロー全体を詳しく解説する。

1 DEEPX NPU Introduction: 高性能と超低消費電力の調和

HW アーキテクチャと超低消費電力設計

DEEPX の DX-M1 は最新 5nm 微細プロセスを基盤として製造され、エッジ環境向けに最適化された 25 TOPS (INT8 基準)の演算性能を提供する AI プロセッサである。単に微細プロセスや高い TOPS 数値に依存しただけでなく、独自アーキテクチャの最適化により、実際の消費電力あたりの推論性能 (Inference-per-Second/Watt) を最大化するよう設計されている点が特徴である。

具体的な消費電力の指標を見ると、その真価がわかる。軽量オブジェクト検出モデル YOLOv9T 稼働時の消費電力は約 2.69W にとどまり、演算量のはるかに多い YOLOv8L を稼働させても 5.64W 程度と非常に低い。ヒートシンクや小型クーリングファンだけで Raspberry Pi 5 と併用できる条件を満たす。

内部ブロックダイアグラムとメモリ階層構造

DX-M1 チップ内部には Cortex-M55 コアとともに 3 つの NPU コア (NPU0, NPU1, NPU2) が搭載され、並列で演算を処理する。また高速データ処理のため LPDDR5 インターフェースをサポートし、DX-M1 M.2 モジュールには 2G LPDDR が 2 個搭載され、PCIe Gen3 x4 レーンでホストデバイスと超高速通信する。

特に注目すべきは、データ再利用 (Data Reuse) を最大化したメモリ階層構造である。深層学習モデルではメモリ帯域幅がボトルネックになりやすいが、DX-M1 は内部 SRAM と最適化されたデータフロー制御設計により、Weight と Activation データの外部メモリアクセス量を最小化する。

2 DX-M1 M.2 NPU で Raspberry Pi 5 を Edge AI システムに変える

M.2 NPU モジュールの概要と HW 取り付け方法

DEEPX DX-M1 M.2 モジュールは産業標準の M.2 2280 Key M form factor を採用している。Raspberry Pi 5 は公式に PCIe インターフェースをサポートするため、NVMe HAT や M.2 拡張ボードを使えばこの NPU モジュールを容易に取り付けられる。


必須 SDK (DX-RT) とドライバの簡易インストール方法

Raspberry Pi 5 は aarch64 (ARM64) アーキテクチャベースの OS を使用する。DEEPX のランタイムソフトウェア DX-RT とデバイスドライバは、aarch64 環境の Ubuntu および Debian OS を公式に完全サポートする。Raspberry Pi デフォルト OS の Debian 13 を基準とした DX-RT および NPU ドライバのインストール手順は以下のとおりである。

🍓 Target (Raspberry Pi 5) 
# Install NPU driver
sudo apt update
wget https://github.com/DEEPX-AI/dx_rt_npu_linux_driver/raw/main/release/2.4.1/dxrt-driver-dkms_2.4.1-2_all.deb
sudo apt install ./dxrt-driver-dkms_2.4.1-2_all.deb

# Install libdxrt runtime
wget https://github.com/DEEPX-AI/dx_rt/raw/main/release/3.3.2/libdxrt_3.3.2_all.deb
sudo apt install ./libdxrt_3.3.2_all.deb

# Create dx-engine wheel
cd /usr/share/libdxrt/python_package && sudo ./make_whl.sh

# Install the bundled dx_engine Python wheel (Use python virtual env)
pip install dx_engine-*.whl

# Reboot the system
sudo reboot
💡 ヒント: sudo ./make_whl.sh はシステム権限で実行されるが、pip install は仮想環境 (venv) 内で権限競合なくインストールすることを推奨する。

DX-M1 M.2 モジュールの firmware (FW) バージョンが低い場合、API 互換性の問題が発生する。以下の手順で NPU FW をアップグレードすること。DX-RT v3.3.2 を基準に、NPU FW バージョン v2.5.6 以上を推奨する。

🍓 Target (Raspberry Pi 5) 
# Upgrade NPU FW to v2.5.6
wget https://github.com/DEEPX-AI/dx_fw/raw/main/m1/2.5.6/mdot2/fw.bin
dxrt-cli -u fw.bin

インストールが正常に完了したか検証する方法は以下のとおりである。

🍓 Target (Raspberry Pi 5) 
# Check the PCIe device status -> expected: 'Processing accelerators: DEEPX...'
lspci | grep acc

# Check the PCIe generation and the number of lane for your NPU
# DX-M1 delivers the best performance on PCIe Gen3 (8GT/s), x4 lane
# Expected for Raspberry Pi 5 -> LnkSta: Speed 8GT/s, Width x1 (downgraded)
sudo lspci -vvv | grep -iA 33 accelerators | grep "LnkSta"

# Check NPU kernel driver status -> expected: dxrt_driver, dx_dma
lsmod | grep dxrt

# Check NPU device files -> expected: '/dev/dxrt0'
ls /dev/dxrt*

# Check NPU daemon status -> expected: dxrt.service - DX-RT Service is active (running) state
systemctl status dxrt.service

# Check the DX-RT and other version info -> expected: DXRT v3.3.2, FW v2.5.6
dxrt-cli -s

# Run a model as a quick validation -> expected: 'FPS: higher than 90'
wget https://sdk.deepx.ai/modelzoo/dxnn/2_3_0/yolo26n.dxnn
run_model -m yolo26n.dxnn -t 3 | grep FPS

PCIe の Speed が 8GT/s ではなく 5GT/s の場合、Raspberry Pi 5 の PCIe が Gen3 ではなく Gen2 に設定されている状態である。以下のリンクを参照して Gen3 に変更すると、NPU の利用効率を高められる。

3 クロスプラットフォーム開発: カスタム AI モデルのポーティング実践

実際の現場で使える「野生動物 detection 監視カメラ」を構築してみよう。開発過程で混同してはいけない概念は コンパイル環境 (Host) とランタイム環境 (Target) の分離である。

野生動物を detection する custom model を開発する過程と、実際に推論を実行するシステムは分けて考える必要がある。AI モデルを開発し DEEPX NPU で動作する .dxnn format への変換までの工程は別途高性能なシステムで行い、実際に AI モデルで推論を実行する Edge Device (例: Raspberry Pi 5 + DX-M1 M.2 module) では DX-Runtime 上で動作する application を開発する。

AI Development Work Flow 全体は、以下の 5 段階で表現できる。

  1. AI Use Case: YOLO26 モデルを使用して Object Detection を実行する。
  2. Data Preparation: Training に使用する dataset を収集し annotation 作業を行う。詳細は 4. 特別付録 を参照する。
  3. Training: 収集した dataset で野生動物を detection する YOLO26 モデルを training により生成する工程である。詳細は 4. 特別付録 を参照する。
  4. Optimization with DX-Compiler: Pre-trained された PyTorch ベースの weight を ONNX format に変換し、DEEPX NPU で使用可能な .dxnn 形式に変換する工程である。4. 特別付録 では Ultralytics platform 経由で Cloud から .dxnn format へ直接 export する方法もある。本稿では Local PC で DX-COM を使って直接 compile する方法を説明する。
  5. Deployment: .dxnnを使って DEEPX NPU 上で推論を実行する object detection application を作成し、実行してみる。

[Host PC] 学習済み野生動物 Detection モデルを DEEPX 向け dxnn format にコンパイルする

DEEPX のコンパイラ DX-COM は x86_64 アーキテクチャの PC 環境でのみ動作する。したがってモデル学習とバイナリコンパイルは開発用 PC で行い、Debian 系 Linux system を推奨する。このシステムに DX-M1 M.2 モジュールは必須ではない。PyTorch 等で学習した weight ファイル (pt) から ONNX format のモデル (例: YOLO26s) を抽出し、DX-COM で DEEPX ハードウェア専用バイナリ format である .dxnnに変換する。

  1. YOLO26s の pre-trained weight をダウンロード: YOLO26s をベースに学習した野生動物 YOLO26 モデルの weight をダウンロードする。yolo26s-custom.pt ファイルがダウンロードされる。(学習の便宜上 pt ファイルを提供するが、custom model の training フローを使用しても差し支えない)

    💻 Host PC (Ubuntu/x86_64) 
    wget -O yolo26s-custom.pt https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/best.pt

  2. 必須パッケージのインストール: ターミナルまたはコマンドプロンプトを開き、Python 仮想環境を作成後、pip で ultralytics パッケージをインストールする。このコマンド一つで数分以内に必要なツールがすべてインストールされる。

    💻 Host PC (Ubuntu/x86_64) 
    # Python 仮想環境の作成と有効化
python -m venv venv
source venv/bin/activate
pip install -U pip

# Install ultralytics & dx-com package
pip install ultralytics dx-com

  3. ONNX 変換: DX-Compiler は ONNX への一次変換が必要であり、それを .dxnnに変換できる。ONNX 抽出時は batch size を必ず 1 に固定する。NPU では low latency が重要なため multi batch size は考慮せず、固定 batch 1 のみ使用する設計である。

    💻 Host PC (Ubuntu/x86_64) 
    # yolo export で ONNX format に抽出 (input size = 640, batch size = 1)
yolo export model=yolo26s-custom.pt format=onnx batch=1 imgsz=640
# wget -O yolo26s-wild.pt https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/yolo26s-custom.onnx

    yolo26s-custom.onnx ファイルが生成されれば成功である。抽出された ONNX ファイルの batch size が 1 に固定されているか https://netron.app で確認する。ブラウザで yolo26s-custom.onnx ファイルを読み込み、最上部の images レイヤーをクリックして input tensor shape が 1x3x640x640 と表示されればよい。

  4. Calibration Data の準備: DX-Compiler の FP32 to INT8 Quantization に使用する calibration 用画像が必要で、最低 100 枚以上を推奨する。実際の input に使う dataset に近いほど accuracy loss を最小化できる。ただし compile 時に実際のデプロイ環境と異なる calibration image を使うと、量子化に実データが反映されず INT8 精度が低下する可能性があるので注意すること。本手順では任意の dataset を使用するが、実運用では必ずデプロイ環境に合った dataset を使用する必要がある。

    💻 Host PC (Ubuntu/x86_64) 
    # DX-Compiler の FP32 to INT8 Quantization 用 calibration 画像をダウンロード
wget "https://sdk.deepx.ai/dataset/calibration_dataset.tar.gz"
tar xzf calibration_dataset.tar.gz

  5. コンパイル configuration の作成: 以下の内容で yolo26s-custom.json ファイルを作成する。詳細は DEEPX 開発者ページの DX-COM user manual を参照する。ドキュメントのダウンロードには、まず DEEPX 開発者ページでアカウントを作成しログインが必要である。 https://developer.deepx.ai/download/?id=510 からダウンロード可能である。

    💻 Host PC (Ubuntu/x86_64) 
    {
  "inputs": { "images": [1, 3, 640, 640] },
  "calibration_num": 100,
  "calibration_method": "ema",
  "train_batchsize": 32,
  "num_samples": 1024,
  "default_loader": {
    "dataset_path": "calibration_dataset",
    "file_extensions": ["jpeg", "jpg", "png", "JPEG"],
    "preprocessings": [
      { "resize": { "mode": "pad", "size": 640, "pad_location": "edge", "pad_value": [114, 114, 114] } },
      { "div": { "x": 255 } },
      { "convertColor": { "form": "BGR2RGB" } },
      { "transpose": { "axis": [2, 0, 1] } },
      { "expandDim": { "axis": 0 } }
    ]
  }
}

  6. DX-COM でコンパイル実行: 設定が完了したら以下のコマンドでコンパイルする。詳細は DEEPX 開発者ページの DX-COM user manual を参照。 https://developer.deepx.ai/download/?id=510 からダウンロード可能である。

    💻 Host PC (Ubuntu/x86_64) 
    dxcom -m yolo26s-custom.onnx -c yolo26s-custom.json -o output

# コンパイル完了後、以下のように yolo26s-custom.dxnn ファイルが生成される。
# ├── output
# │   └── yolo26s-custom.dxnn

    生成された yolo26s-custom.dxnn を target device (Raspberry Pi 5) にコピーする。上記工程を省略し、コンパイル済みの .dxnn ファイルのみ取得して次の工程に進む場合は、以下のリンクから野生動物 detection 用のコンパイル済み yolo26s-custom.dxnn ファイルをダウンロードできる。

    💻 Host PC (Ubuntu/x86_64) 
    wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/yolo26s-custom.dxnn"

[Raspberry Pi 5 Target] DX-APP を使った Custom YOLO26 Object Detection Application の実装

    🍓 Target (Raspberry Pi 5) 
    #!/bin/bash
# =========================================================
# Configuration (ユーザー設定領域)
# =========================================================
NUM_PIPELINES=4
OUTPUT_WIDTH=1280
OUTPUT_HEIGHT=720

MODEL_NAME="yolo26s-custom.dxnn"
POSTPROCESS_LIB="/usr/local/share/gstdxstream/lib/libpostprocess_yolo26od.so"

# =========================================================
# Grid Layout Calculation
# =========================================================
COLS=1
while [[ $((COLS * COLS)) -lt ${NUM_PIPELINES} ]]; do
    COLS=$((COLS + 1))
done
ROWS=$(((NUM_PIPELINES + COLS - 1) / COLS))

STREAM_WIDTH=$((OUTPUT_WIDTH / COLS))
STREAM_HEIGHT=$((OUTPUT_HEIGHT / ROWS))

echo "=================================================="
echo " Pipeline Configuration"
echo " - Streams: ${NUM_PIPELINES}"
echo " - Grid: ${ROWS} rows x ${COLS} columns"
echo " - Individual Stream Size: ${STREAM_WIDTH}x${STREAM_HEIGHT}"
echo " - Total Output Resolution: ${OUTPUT_WIDTH}x${OUTPUT_HEIGHT}"
echo "=================================================="

# =========================================================
# Pipeline Generation
# =========================================================
PIPELINE_STR=""
COMPOSITOR_PROPS=""

for i in $(seq 0 $((NUM_PIPELINES - 1))); do
    VIDEO_FILE="test-video-$((i+1)).mp4"
    URI="file://$(pwd)/${VIDEO_FILE}"

    # Calculate x, y positions for the compositor
    ROW_IDX=$((i / COLS))
    COL_IDX=$((i % COLS))
    X_POS=$((COL_IDX * STREAM_WIDTH))
    Y_POS=$((ROW_IDX * STREAM_HEIGHT))

    echo " Adding stream ${i}: ${VIDEO_FILE}"

    # Build the individual stream pipeline
    SRC_PIPE="urisourcebin uri=\"${URI}\" ! queue max-size-buffers=6 ! decodebin ! queue max-size-buffers=6 ! \
        dxpreprocess preprocess-id=1 resize-width=640 resize-height=640 ! queue max-size-buffers=6 ! \
        dxinfer preprocess-id=1 inference-id=1 model-path=\"${MODEL_NAME}\" ! queue max-size-buffers=6 ! \
        dxpostprocess inference-id=1 library-file-path=\"${POSTPROCESS_LIB}\" function-name=PostProcess ! queue max-size-buffers=6 ! \
        dxosd ! queue max-size-buffers=6 ! \
        dxscale width=${STREAM_WIDTH} height=${STREAM_HEIGHT} ! queue max-size-buffers=6 ! comp.sink_${i}"

    PIPELINE_STR="${PIPELINE_STR} ${SRC_PIPE}"
    COMPOSITOR_PROPS="${COMPOSITOR_PROPS} sink_${i}::xpos=${X_POS} sink_${i}::ypos=${Y_POS}"
done

# =========================================================
# Launch Pipeline
# =========================================================
LAUNCH_CMD="gst-launch-1.0 -e ${PIPELINE_STR} compositor name=comp ${COMPOSITOR_PROPS} ! videoconvert ! fpsdisplaysink sync=false"

echo "--------------------------------------------------"
echo "Launching GStreamer pipeline..."
echo "--------------------------------------------------"

eval "${LAUNCH_CMD}"

exit 0
💡 ヒント: Multi-stream pipeline 実装時、すべて同一 AI モデルを使う場合は、必ずしも dxpreprocess → dxinfer → dxpostprocess を stream ごとに分離する必要はない。むしろ dxinputselector と dxoutputselector を使えば各 stream が plugin を共有でき、同一モデルを NPU に重複 load するリソース浪費を最小化できる。
以下の pipeline 構造図はその実装例であり、dx_stream/pipelines/multi_stream/run_multi_stream_selector.sh を参照すると実装の詳細がわかる。

4 特別付録: 独自 YOLO26 custom モデル学習ガイド

最新オブジェクト検出モデル YOLO26 は NMS (Non-Maximum Suppression) 後処理不要の End-to-End 推論をサポートし、edge device 向けに最適化された次世代 Vision AI モデルである。初めての方でも独自 dataset を構築し YOLO26 を学習できるよう、2 つの方法を紹介する。

参考用 dataset は以下のリンクからダウンロード可能である。当該 dataset は IP 上の理由で少量の data のみ含むため、概念理解用として使用すること。研究目的の精度を得るには最低 1000 枚以上の dataset が必要であり、商用化目的の精度を得るには最低 10000 枚以上の多様な dataset が必要である。

Dataset 作成とファイル/フォルダ構造

YOLO モデルの学習には、画像ファイル群と各画像内のオブジェクト位置 (Bounding box) を記録したラベルテキストファイルが必要である。Ultralytics プラットフォームとモデルは YOLO、COCO、VOC など多様な format を広くサポートする。一般的な custom dataset のフォルダ構造は以下のとおりである。

学習方法 1: Ultralytics Platform の利用 (Cloud 環境、初心者向け)

コーディングや別途 PC 環境設定なしで、Web ブラウザ GUI から手軽に学習できる方法である。

  1. アクセスとデータアップロード: https://platform.ultralytics.com にログインし、新規プロジェクトを作成して raw 画像をアップロードする。
  2. スマートラベリング: プラットフォーム内蔵の AI ベース Smart Annotation ツールで、クリック一回でバウンディングボックスを自動生成できる。この機能により手作業比最大 10 倍速く高品質 dataset を完成できる。
  3. Cloud Training - New Model: アノテーション完了後、プラットフォームの cloud GPU でモデル学習をすぐ開始できる。GPU なしで学習にかかる日数を短縮でき、精度などの指標をリアルタイムでモニタリングできる。New Model を選択する。

  4. Cloud Training - Base Model: base となるモデルを選定する。

  5. Cloud Training - Start Training: Cloud training は従量課金で、約 1300 枚の dataset を yolo26n で training すると約 $0.34 の credit を消費する。Account 作成時に企業 email で登録すると $25 free credit が付与される。

  6. エクスポート: 学習完了後、完成モデルを export すると yolo26n.dxnn が生成され、ダウンロードして NPU 推論にそのまま使用できる。

YOLO26 モデルの scale 別性能比較

Ultralytics YOLO26 シリーズのモデル名末尾の n, s, m, l, x はモデルのサイズ (Scale) と演算複雑度による区分である。要約すると「パラメータ数 (容量) と演算量 (速度) のバランスによる区分」である。アルファベットはそれぞれ次を意味する。

  1. n (Nano): 最小・最軽量モデル (速度最優先、超軽量デバイス向け)
  2. s (Small): 小型モデル (速度と精度の良い妥協点)
  3. m (Medium): 中サイズモデル (バランスの取れた性能)
  4. l (Large): 大型モデル (高精度が必要な場合)
  5. x (XLarge): 最大モデル (速度より精度最優先)

Raspberry Pi 5 + DX-M1 M.2 で YOLO26 モデルの性能を測定した結果は以下のとおりである。

Model FPS Accuracy (mAP)
YOLO26n 110.56 39.256
YOLO26s 109.96 46.767
YOLO26m 96.81 51.261
YOLO26l 70.10 53.149
YOLO26x 40.12 55.115
