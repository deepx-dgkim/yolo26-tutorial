使用 DEEPX M1 NPU 和 Raspberry Pi 5 构建超低功耗 Edge AI 系统

在智能工厂、自动驾驶、机器人、智能安防监控(CCTV)等工业物理边缘(Physical Edge)场景中，最核心的技术是高速、高精度的 AI。在这些场景中，将高分辨率摄像头的流数据传输到 cloud server 处理的传统 cloud 方式会带来以下几个致命问题:

  • 延迟 (Latency): 网络往返时间使毫秒(ms)级的即时响应变得不可能
  • 带宽与成本 (Bandwidth & Cost): 数十至数百台高清摄像头 24 小时不间断串流所产生的过量网络流量和运营成本
  • 隐私与安全 (Privacy & Security): 现场敏感视频数据泄露到外部网络的风险
  • 连接性/稳定性 (Connectivity/Stability): 网络故障或偏远环境下系统整体停机的风险

为了解决上述问题，Edge AI 技术应运而生。得益于近年来 Edge AI 技术的进步，无需经过庞大的 cloud server，也能在设备端直接实时处理复杂的 AI 模型。但是，受限的功耗、发热，以及嵌入式板卡有限的计算资源，仍然是工程师们必须解决的课题。

本文将介绍如何将全球应用最广泛的单板计算机 'Raspberry Pi 5' 与 DEEPX 的超低功耗高性能 AI 加速器 'DX-M1 M.2 模块' 结合，构建一套强大的 Edge AI 系统。我们将从硬件架构入手，深入讲解野生动物检测 custom 模型的开发与移植，直至一个实用的野生动物监控摄像头 demo，完整覆盖 Edge AI 开发的整个工作流程。

1 DEEPX NPU Introduction: 强大性能与超低功耗的结合

HW 架构与超低功耗设计

DEEPX 的 DX-M1 采用最新 5nm 制程打造，提供针对边缘场景优化的 25 TOPS (INT8 基准) 强大算力，是一款 AI 处理器。它并非仅仅依赖先进制程或高 TOPS 数值，而是通过自研架构优化，最大化实际功耗下的推理性能(Inference-per-Second/Watt)，这正是其设计上的一大特点。

从具体的功耗指标就能看出它的价值所在。运行轻量级目标检测模型 YOLOv9T 时，功耗仅约 2.69W；即便运行运算量更大的 YOLOv8L，功耗也仅约 5.64W。仅凭散热片或小型风扇散热，就足以与 Raspberry Pi 5 一起稳定运行。

那么实际的推理速度究竟能提升多少?我们在同一台 Raspberry Pi 5 上，以运算量较大的 YOLO26-l (640x640) 模型为基准，实测比较了仅用 CPU 推理与使用 DX-M1 NPU 推理的速度差异。

内部框图与内存层级结构

DX-M1 芯片内部搭载了 Cortex-M55 核心以及 3 个 NPU 核心(NPU0、NPU1、NPU2)以实现并行运算。它还支持 LPDDR5 接口以实现高速数据处理，DX-M1 M.2 模块上搭载了 2 颗 2GB 的 LPDDR，并通过 PCIe Gen3 x4 通道与主机进行超高速通信。

尤其值得关注的是最大化数据复用(Data Reuse)的内存层级结构。深度学习模型的特性容易导致内存带宽成为瓶颈，而 DX-M1 通过内部 SRAM 与经过优化的数据流控制设计，最大限度地减少了 Weight 与 Activation 数据的外部内存访问量。

2 使用 DX-M1 M.2 NPU 将 Raspberry Pi 5 打造成 Edge AI 系统

DEEPX NPU 大致分为两种类型: DX-M1 和 DX-M1M。下面我们介绍两种配置方式: 一种使用 DX-M1 M.2 模块，另一种使用 DX-M1M 一体式 HAT。

DX-M1 M.2 NPU 模块简介及硬件安装方法

DEEPX DX-M1 M.2 模块采用了业界标准的 M.2 2280 Key M form factor。Raspberry Pi 5 官方支持 PCIe 接口，因此使用 NVMe HAT 或 M.2 扩展板即可轻松安装该 NPU 模块。


DX-M1M 模块简介及一体式 HAT 安装方法

DEEPX DX-M1M 芯片是一款内置 1GB 或 2GB DDR4 RAM 的解决方案。相较于使用 DDR5 RAM 的 DX-M1，其推理性能约低 20%，但在价格与芯片尺寸上具有优势。DEEPX 与 Sixfab 合作，推出了将 DX-M1M 芯片以板载(on-board)形式搭载的产品，提供了经过 Raspberry Pi 5 验证的 AI HAT form factor。硬件可以按以下方式安装使用。

安装 DX-RT SDK 及驱动

Raspberry Pi 5 运行 aarch64 (ARM64) 架构。DEEPX 的 DX-RT 与 NPU 驱动正式支持 aarch64 环境下的 Ubuntu 与 Debian。以下以 Raspberry Pi 默认 OS Debian 13 为例，说明 DX-RT 及 NPU 驱动的安装步骤。

🍓 Target (Raspberry Pi 5) 
# Install NPU driver
sudo apt update
wget https://github.com/DEEPX-AI/dx_rt_npu_linux_driver/raw/main/release/2.5.1/dxrt-driver-dkms_2.5.1-2_all.deb
sudo apt install ./dxrt-driver-dkms_2.5.1-2_all.deb

# Install libdxrt runtime
wget https://github.com/DEEPX-AI/dx_rt/raw/main/release/3.4.0/libdxrt-bin_3.4.0_arm64.deb
sudo apt install ./libdxrt-bin_3.4.0_arm64.deb

# Reboot the system
sudo reboot

如果 DX-M1 M.2 模块的 firmware(FW) 版本过低，会发生 API 兼容性问题。因此需要按以下方式升级 NPU FW。以 DX-RT v3.4.0 为基准，建议 NPU FW 版本为 v2.7.3 以上。

🍓 Target (Raspberry Pi 5) 
# Stop dxrt.service before FW upgrade
systemctl stop dxrt.service

# Download NPU FW v2.7.3
wget https://github.com/DEEPX-AI/dx_fw/raw/main/m1/2.7.3/mdot2/fw.bin

# For DX-M1M module, you need to download the M1M FW bin instead of the M1 FW bin
# wget https://github.com/DEEPX-AI/dx_fw/raw/main/m1m/2.7.3/mdot2/fw.bin

# Upgrade NPU FW to v2.7.3
dxrt-cli -u fw.bin

# Restart dxrt.service after FW upgrade
systemctl start dxrt.service

3 跨平台开发: Custom AI 模型移植实战

接下来让我们构建一套实际现场可用的"野生动物 detection 监控摄像头"。开发过程中不能混淆的一个概念是 编译环境(Host)与运行环境(Target)的分离。

开发用于检测野生动物的 custom model 的过程，与实际执行推理的系统需要分开考虑。开发 AI 模型并将其转换为可在 DEEPX NPU 上运行的 .dxnn format 的过程，应在另一台性能优秀的系统上进行；而在实际使用该模型执行推理的 Edge Device (例如: Raspberry Pi 5 + DX-M1 M.2 module) 上，则需要开发运行在 DX-Runtime 之上的 application。

整个 AI Development Work Flow 可以用以下 5 个步骤来表示。

  1. AI Use Case: 使用 YOLO26 模型执行 Object Detection。
  2. Data Preparation: 收集用于 Training 的 dataset 并进行 annotation 工作。详细内容请参考 4. 附录。
  3. Training: 利用已收集的 dataset，通过 training 生成用于检测野生动物的 YOLO26 模型。详细内容请参考 4. 附录。
  4. Optimization with DX-Compiler: 将 pre-trained 的 PyTorch weight 转换为 ONNX format，再转换为可在 DEEPX NPU 上使用的 .dxnn format 的过程。4. 附录 中还介绍了通过 Ultralytics platform 直接从 Cloud export 为 .dxnn format 的方法；这里我们介绍在 Local PC 上使用 DX-COM 直接 compile 的方法。
  5. Deployment: 使用 .dxnn 构建一个能在 DEEPX NPU 上执行推理的 object detection application 并运行它。

[Host PC] 将训练好的野生动物检测模型编译为 DEEPX 可用的 dxnn format

DEEPX 的编译器 DX-COM 只能在 x86_64 架构的 PC 环境中运行。因此模型训练与二进制编译需要在开发用 PC 上进行，推荐使用 Debian 系 Linux system。该系统并不一定需要配备 DX-M1 M.2 模块。从通过 PyTorch 等训练得到的 weight 文件(pt)中提取 ONNX format 的模型(例如: YOLO26s)后，再用 DX-COM 将其转换为 DEEPX 硬件专用的二进制 format .dxnn。

  1. 下载 YOLO26s pre-trained weight: 下载基于 YOLO26s 训练得到的野生动物 YOLO26 模型的 weight 值，会得到 yolo26s-custom.pt 文件。(为方便起见提供了该 pt 文件，你也可以使用自己训练的 custom model 的 weight(pt) 文件替代)

    💻 Host PC (Ubuntu/x86_64) 
    wget -O yolo26s-custom.pt https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/best.pt

  2. 安装必要的软件包: 打开终端或命令行窗口，创建 Python 虚拟环境后，使用 pip 命令安装 ultralytics 软件包。仅需这一条命令，几分钟内即可完成所有必需工具的安装。

    💻 Host PC (Ubuntu/x86_64) 
    # Create and activate Python virtual environment
python -m venv venv
source venv/bin/activate
pip install -U pip

# Install ultralytics & dx-com package
pip install ultralytics dx-com

  3. 转换为 ONNX: DX-Compiler 需要先转换为 ONNX，才能进一步转换为 .dxnn。导出 ONNX 时必须将 batch size 固定为 1。因为 NPU 在设计上追求 low latency，不考虑 multi batch size，只使用固定的单个 batch。

    💻 Host PC (Ubuntu/x86_64) 
    # Export to ONNX with yolo export (input size = 640, batch size = 1)
yolo export model=yolo26s-custom.pt format=onnx batch=1 imgsz=640
# wget -O yolo26s-wild.pt https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/yolo26s-custom.onnx

    当 yolo26s-custom.onnx 文件生成后即为成功。可以在 https://netron.app 中打开该文件，点击最上方的 images 层，确认 input tensor shape 显示为 1x3x640x640。

  4. 准备 calibration 数据: DX-Compiler 在进行 FP32 到 INT8 量化时需要 calibration 图像，建议至少准备 100 张以上。图像越接近实际 input 所使用的 dataset，就越能降低 accuracy loss。但如果在 compile 时使用与实际部署环境不同的 calibration image，会导致量化过程无法反映真实数据，从而降低 INT8 精度，需要注意这一点。本教程使用的是任意 dataset，实际使用时必须使用与部署环境相匹配的 dataset。

    💡 提示: 什么是 calibration 图像? 将 FP32 模型转换为 INT8(量化，quantization)可以减小模型体积和计算量，但可能引入精度损失。calibration 图像的作用就是最大限度降低这种损失: 让少量图像通过模型进行一次前向传播(forward pass)，以统计方式测量各 layer 的 activation 值分布(range)，并据此计算出最优的 quantization scale/zero-point 值。与训练用 dataset 不同，calibration 图像不需要 label，也不会更新任何权重，仅作为观察 activation 范围的样本输入。
    💻 Host PC (Ubuntu/x86_64) 
    # Download calibration images for FP32 to INT8 quantization in DX-Compiler
wget "https://sdk.deepx.ai/dataset/calibration_dataset.tar.gz"
tar xzf calibration_dataset.tar.gz

  5. 创建编译 configuration: 按以下内容创建 yolo26s-custom.json 文件。详细内容请参考 DEEPX 开发者网站上的 DX-COM user manual (需要登录)。 下载地址: https://developer.deepx.ai/download/?id=510

    💻 Host PC (Ubuntu/x86_64) 
    {
  "inputs": { "images": [1, 3, 640, 640] },
  "calibration_num": 100,
  "calibration_method": "ema",
  "train_batchsize": 32,
  "num_samples": 1024,
  "default_loader": {
    "dataset_path": "calibration_dataset",
    "file_extensions": ["jpeg", "jpg", "png", "JPEG"],
    "preprocessings": [
      { "resize": { "mode": "pad", "size": 640, "pad_location": "edge", "pad_value": [114, 114, 114] } },
      { "div": { "x": 255 } },
      { "convertColor": { "form": "BGR2RGB" } },
      { "transpose": { "axis": [2, 0, 1] } },
      { "expandDim": { "axis": 0 } }
    ]
  }
}

  6. 使用 DX-COM 进行编译: 配置完成后，运行以下命令进行编译。详细内容请参考 DEEPX 开发者网站上的 DX-COM user manual。 下载地址: https://developer.deepx.ai/download/?id=510

    💻 Host PC (Ubuntu/x86_64) 
    dxcom -m yolo26s-custom.onnx -c yolo26s-custom.json -o output

# After compile, yolo26s-custom.dxnn is created under output/
# ├── output
# │   └── yolo26s-custom.dxnn

    将 yolo26s-custom.dxnn 复制到 target device(Raspberry Pi 5)。如果想省略以上过程，直接获取已编译好的 .dxnn 文件进行后续步骤，可以从以下链接下载已编译好的野生动物检测用 yolo26s-custom.dxnn 文件。

    💻 Host PC (Ubuntu/x86_64) 
    wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/yolo26s-custom.dxnn"

[Raspberry Pi 5 Target] 使用 DX-APP 实现 Custom YOLO26 Object Detection

将编译好的 .dxnn 文件转移到 Raspberry Pi 5 后，就可以执行推理了。要在 DEEPX NPU 上运行 YOLO26 模型的 application，最简单的方式是修改 DEEPX 提供的 sample code。DX-APP 为 DEEPX Model Zoo 中所有已验证的 AI 模型都提供了 1:1 对应的 sample application code，同时支持 C++ 和 Python 两个版本。

DEEPX Model Zoo 提供了目前 DEEPX 已验证的 AI 模型的编译前 ONNX 文件、编译后的 .dxnn 文件、编译 configuration 文件以及 sample application code，其中包含 sample application code 的组件就是 DX-APP。详情可参见 https://developer.deepx.ai/modelzoo/。

让我们使用 DX-APP 轻松构建自己 YOLO26 模型的 Application。

  1. 克隆 DX-APP repository: 通过 git clone 命令克隆 dx_app git repository。

    🍓 Target (Raspberry Pi 5) 
    git clone https://github.com/DEEPX-AI/dx_app
cd dx_app

  2. 提取 yolo26s object detection 示例代码: 使用 DX-APP 提供的 script 只提取所需的 sample 代码。此过程仅提取并使用与 object_detection/yolo26s 相关的代码。

    🍓 Target (Raspberry Pi 5) 
    # Execute the script to display a selection menu.
./scripts/dx_tool.sh

  3. 通过 config.json 配置只识别 4 个 class 的 Custom 模型: 现有 YOLO26 模型默认是针对识别 80 个 class 进行 pre-trained 的。这里不去修改 DX-APP 共享框架代码本身，而是在示例自身的 config.json 中声明 custom class。DX-APP 的所有示例都已经支持 --config 选项(省略时会自动检测脚本旁的 config.json)，factory 会在创建 postprocessor 和 visualizer 之前合并这些配置值。详细内容请参考 DX-APP YOLO Customizing Guide 的 Step 3 ("Tune config.json"，github.com/DEEPX-AI/dx_app → docs/source/docs/12_DX-APP_YOLO_Customizing_Guide.md)。

    在 config.json 中添加 num_classes 和 class_names:

    🍓 Target (Raspberry Pi 5) 
    {
    "score_threshold": 0.25,
    "nms_threshold": 0.45,
    "num_classes": 4,
    "class_names": ["Person", "Deer", "Raccoon", "Bear"]
}

    postprocessor 已经会读取 config.json 中的 num_classes(默认值为 80)。源码上唯一需要的修改，是在生成的示例自身的 factory/yolo26s_factory.py 中改一行代码，让 visualizer 使用 class_names —— 而不需要触碰共享的 common/ 库:

    🍓 Target (Raspberry Pi 5) 
    --- a/src/python_example/object_detection/yolo26s/factory/yolo26s_factory.py
+++ b/src/python_example/object_detection/yolo26s/factory/yolo26s_factory.py
@@
     def create_visualizer(self):
-        return DetectionVisualizer()
+        return DetectionVisualizer(custom_labels=self.config.get('class_names'))

    从此以后，如果想切换到不同的 class 组合或阈值，只需修改 config.json 即可 —— 无需重新构建或重新 patch 示例代码。

  4. 运行 app: 下载测试视频，在虚拟环境中安装 dx_engine 和 opencv-python，然后执行 yolo26s_async.py 运行一个简单的野生动物检测 demo。这里显式传入 --config 是为了让 class 组合的选择过程更直观(省略时也会自动检测脚本旁的 config.json)。

    🍓 Target (Raspberry Pi 5) 
    # Test Video download
wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/test-video-0.mp4"
wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/test-video-1.mp4"
wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/test-video-2.mp4"
wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/test-video-3.mp4"
wget "https://github.com/deepx-dgkim/yolo26-tutorial/raw/main/assets/test-video-4.mp4"

# Create venv and install dx_engine and opencv-python
python3 -m venv venv
source venv/bin/activate
pip install -U pip
pip install dx-engine

[Raspberry Pi 5 Target] 使用 DX-STREAM 实现 Multi-Stream YOLO26 Detection

DX-STREAM 是一个基于 GStreamer 的视频处理平台，提供多种视频处理功能。其中就包括 Object Detection 功能，可以借助它实现 Multi-Stream YOLO26 Object Detection。

让我们使用 DX-STREAM，轻松构建自己 YOLO26 模型的 Multi-Stream Object Detection Application。

  1. 克隆并安装 DX-STREAM: 通过 git clone 克隆 dx_stream git repository，并按以下步骤安装。

    🍓 Target (Raspberry Pi 5) 
    git clone https://github.com/DEEPX-AI/dx_stream.git

./build.sh # run build script

  2. 验证 DX-STREAM: 执行 run_demo.sh 并选择选项 0。如果出现 YOLO26n 检测 demo，说明运行正常。

  5. 四路 GStreamer pipeline: 使用你的 .dxnn 模型和测试视频构建并部署一个 4 路 pipeline。

    🍓 Target (Raspberry Pi 5) 
    #!/bin/bash
# =========================================================
# Configuration (user settings)
# =========================================================
NUM_PIPELINES=4
OUTPUT_WIDTH=1280
OUTPUT_HEIGHT=720

MODEL_NAME="yolo26s-custom.dxnn"
POSTPROCESS_LIB="/usr/local/share/gstdxstream/lib/libpostprocess_yolo26od.so"

# =========================================================
# Grid Layout Calculation
# =========================================================
COLS=1
while [[ $((COLS * COLS)) -lt ${NUM_PIPELINES} ]]; do
    COLS=$((COLS + 1))
done
ROWS=$(((NUM_PIPELINES + COLS - 1) / COLS))

STREAM_WIDTH=$((OUTPUT_WIDTH / COLS))
STREAM_HEIGHT=$((OUTPUT_HEIGHT / ROWS))

echo "=================================================="
echo " Pipeline Configuration"
echo " - Streams: ${NUM_PIPELINES}"
echo " - Grid: ${ROWS} rows x ${COLS} columns"
echo " - Individual Stream Size: ${STREAM_WIDTH}x${STREAM_HEIGHT}"
echo " - Total Output Resolution: ${OUTPUT_WIDTH}x${OUTPUT_HEIGHT}"
echo "=================================================="

# =========================================================
# Pipeline Generation
# =========================================================
PIPELINE_STR=""
COMPOSITOR_PROPS=""

for i in $(seq 0 $((NUM_PIPELINES - 1))); do
    VIDEO_FILE="test-video-$((i+1)).mp4"
    URI="file://$(pwd)/${VIDEO_FILE}"

    # Calculate x, y positions for the compositor
    ROW_IDX=$((i / COLS))
    COL_IDX=$((i % COLS))
    X_POS=$((COL_IDX * STREAM_WIDTH))
    Y_POS=$((ROW_IDX * STREAM_HEIGHT))

    echo " Adding stream ${i}: ${VIDEO_FILE}"

    # Build the individual stream pipeline
    SRC_PIPE="urisourcebin uri=\"${URI}\" ! queue max-size-buffers=6 ! decodebin ! queue max-size-buffers=6 ! \
        dxpreprocess preprocess-id=1 resize-width=640 resize-height=640 ! queue max-size-buffers=6 ! \
        dxinfer preprocess-id=1 inference-id=1 model-path=\"${MODEL_NAME}\" ! queue max-size-buffers=6 ! \
        dxpostprocess inference-id=1 library-file-path=\"${POSTPROCESS_LIB}\" function-name=PostProcess ! queue max-size-buffers=6 ! \
        dxosd ! queue max-size-buffers=6 ! \
        dxscale width=${STREAM_WIDTH} height=${STREAM_HEIGHT} ! queue max-size-buffers=6 ! comp.sink_${i}"

    PIPELINE_STR="${PIPELINE_STR} ${SRC_PIPE}"
    COMPOSITOR_PROPS="${COMPOSITOR_PROPS} sink_${i}::xpos=${X_POS} sink_${i}::ypos=${Y_POS}"
done

# =========================================================
# Launch Pipeline
# =========================================================
LAUNCH_CMD="gst-launch-1.0 -e ${PIPELINE_STR} compositor name=comp ${COMPOSITOR_PROPS} ! videoconvert ! fpsdisplaysink sync=false"

echo "--------------------------------------------------"
echo "Launching GStreamer pipeline..."
echo "--------------------------------------------------"

eval "${LAUNCH_CMD}"

exit 0
💡 提示: 当所有 stream 都使用同一个模型时，并不需要为每个 stream 单独构建一套 dxpreprocess → dxinfer → dxpostprocess 链路。可以使用 dxinputselector 和 dxoutputselector 让这些 plugin 被多个 stream 共享，避免在 NPU 上重复加载同一模型所造成的资源浪费。
参见下方的结构图以及 dx_stream/pipelines/multi_stream/run_multi_stream_selector.sh。

训练方法 1: 使用 Ultralytics Platform (Cloud 环境，适合初学者)

Ultralytics Platform 是一个一站式平台，覆盖了从 dataset annotation 到 cloud 训练、模型 export 的完整计算机视觉 AI 工作流。它提供基于 SAM 的 Smart Annotation 大幅加快标注速度，还提供基于 NVIDIA GPU 的 cloud 训练以及多种格式的 export 功能。

无需本地环境配置或编写代码，即可在浏览器中完成训练。

  1. 登录并上传: 登录 https://platform.ultralytics.com，创建一个项目并上传图像。
  2. 智能标注: 使用 Smart Annotation 自动生成边界框 —— 比手动标注快约 10 倍。
  3. Cloud Training - New Model: 标注完成后，即可在 cloud GPU 上开始训练，实时查看各项指标，并选择 New Model。

  4. Cloud Training - Base Model: 选择用于训练的基础 YOLO 模型。

  5. Cloud Training - Start Training: Cloud 训练为付费服务(约 1,300 张图像用 yolo26n 训练约消耗 $0.34 credit)。使用企业邮箱注册可获得 $25 免费 credit。

  6. 导出: 导出训练好的模型即可得到可直接用于 NPU 推理的 yolo26n.dxnn。

更多细节请参考以下 Ultralytics DEEPX Integration Guide。
👉 参考链接: https://github.com/ultralytics/ultralytics/blob/main/docs/en/integrations/deepx.md

YOLO26 不同 Model Scale 的性能对比

在 YOLO26 的命名中，n、s、m、l、x 表示模型的大小和计算量。简单来说，就是在模型大小(参数量)与速度之间进行权衡。

  1. n (Nano): 最小、最轻量(速度优先，适合微型设备)
  2. s (Small): 小型模型(速度与精度的平衡)
  3. m (Medium): 中等大小(整体均衡)
  4. l (Large): 大型模型(需要更高精度时使用)
  5. x (XLarge): 最大(精度优先于速度)

在 Raspberry Pi 5 + DX-M1 M.2 上的基准测试结果:

Model (640x640) FPS Accuracy (mAP)
YOLO26n 110.56 39.256
YOLO26s 109.96 46.767
YOLO26m 96.81 51.261
YOLO26l 70.10 53.149
YOLO26x 40.12 55.115

本次测量所用的 .dxnn 文件下载自 DEEPX Official Model Zoo (https://developer.deepx.ai/modelzoo/)。

测量命令示例: run_model -m yolo26s.dxnn --use-ort -t 3 (按 scale 更改模型名称: yolo26n.dxnn、yolo26s.dxnn 等)
